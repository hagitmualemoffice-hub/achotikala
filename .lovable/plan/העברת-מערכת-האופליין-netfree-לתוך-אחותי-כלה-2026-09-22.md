# העברת מערכת האופליין (NetFree) לתוך אחותי כלה

## מה בדקתי (עובדות, לא הנחות)

**1. חיבור GitHub לפרויקט הזה:** אין. ה-remote היחיד הוא ה-git הפנימי של Lovable
(`git.private.lovable-gcp.code.storage/c12601da-…`) + מראה ב-S3. אין remote של github.com,
כלומר סנכרון GitHub לא מחובר ויש לחבר אותו ידנית.

**2. קראתי את הקוד הישן** (הריפו הציבורי `hagitmualemoffice-hub/connect-thrive`).
הקבצים לא נמצאים ב-`public/` אלא תחת `offline-dist/`:
`offline-dist/downloads/achoti-kalah.html` (47.6KB, BOOT_REV 9),
`offline-dist/updates/manifest.js|json`, `offline-dist/updates/parts/<hash>.<i>.js`,
`scripts/sync-offline-from-live.mjs`, `scripts/verify-offline-publish.mjs`,
`scripts/offline-parts-registry.json`, `docs/OFFLINE-ARCHITECTURE.md`,
`docs/OFFLINE-UPDATE-PROCEDURE.md`. גרסה תקינה אחרונה: 49 — 72 קבצים / 212 חלקים.

המנגנון בפועל:
- `ORIGIN = qs.get("origin") || "https://hagitmualem.com"` (שורה 45) — נקודת השינוי היחידה לכתובת.
- תעבורה רק דרך `<script src>` (בלי fetch/XHR/ZIP/bin). מניפסט: `ORIGIN + "/updates/manifest.js?t=…&nonce=…"` שקורא ל-`window.AKUPD_MANIFEST(manifest)`.
- חלקים: `ORIGIN + meta.u` כאשר `meta.u = "/updates/parts/<hash>.<i>.js"`, כל חלק קורא `AK.part(hash, index, total, b64, masked)`.
- `CHUNK_RAW = 32*1024`, `masked = 0` (XOR key נשמר לתאימות לאחור בלבד), checksum DJB2, שדות `u`/`l`/`c`, אימות אורך+חתימה לכל חלק (עד 4 ניסיונות) ואימות חתימת הקובץ השלם לפני שמירה.
- ערבול 24 בתים ראשונים בקבצים בינאריים (`HDR_LEN=24`, `HDR_XOR=0x5a`) — זה התיקון לחתימת JPEG.
- IndexedDB `achotikala-app`, stores `blobs`/`meta`, מפתחות `current`/`previous`/`boot`/`updateLog`; `onabort` מטופל, health-check מסמן `verified` מיד אחרי mount, rollback אחרי שני כשלונות, `stale stage` מאלץ הורדה מחדש.
- ההתקנה הראשונה (`firstRun`) עושה בדיוק את מה שנחסם: manifest + כל 212 החלקים ברשת.

**3. מקור התוכן לאריזה:** הסקריפט הישן הוריד את `https://achotikala.com` ב-HTTP.
מכיוון שאנחנו עובדים בתוך הפרויקט הזה, מומלץ לארוז מתוך תיקיית ה-build המקומית
(`vite.offline.config.ts` → `offline-dist/`) ולא מהאתר החי: זה עובד גם כשהאתר החסום/לא זמין,
נותן התאמה מדויקת ל-fingerprint של הקוד, מונע אריזה של גרסה חיה שאינה מה שבנינו,
וחוסך עשרות בקשות HTTP. הסקריפט יישאר עם דגל `--source <url>` כגיבוי.

## הארכיטקטורה החדשה

```text
התקנה ראשונה:  Google Drive  ->  קובץ HTML אחד, עצמאי לחלוטין (כולל כל התוכן בתוכו)
עדכונים:        GitHub (ריפו ציבורי של הפרויקט הזה)  ->  cdn.jsdelivr.net/gh/...
```

### התקנה ראשונה כקובץ HTML עצמאי — אפשרי, בלי שכתוב
הקובץ יהיה בדיוק אותו launcher, ואחריו בלוקים `<script>` פנימיים שקוראים
`AK.part(...)` עם אותו base64 של אותם חלקי 32KB, ועוד `AKUPD_MANIFEST(...)` פנימי.
כלומר אותו פורמט, אותם checksums, אותה לוגיקה של אימות/שמירה/health-check/rollback —
רק שהחלקים מגיעים מהקובץ עצמו במקום מהרשת. אפס בקשות רשת בהתקנה הראשונה.
השינוי היחיד ב-launcher: כ-15 שורות — דילוג על `loadPartScript` כשהחלק כבר קיים ב-`partSinks`,
ודחיית תחילת הריצה עד שבלוקי ה-seed נטענו. לוגיקת העדכונים הרגילה נשארת ללא שינוי.

## תוכנית העבודה

### קבצים שאצור בפרויקט הזה
1. `offline/launcher.html` — ה-launcher המועבר, `BOOT_REV = 10`, `ORIGIN` חדש ל-jsDelivr, תמיכת seed.
2. `scripts/pack-offline.mjs` — אורז מ-`offline-dist/` (build מקומי): hash לכל קובץ, חלקים 32KB, `masked=0`, ערבול 24 בתים לבינאריים, DJB2, שימוש חוזר בחלקים לא-שינויים, מחיקת orphans, כתיבת `manifest.js|json`.
3. `scripts/build-offline-package.mjs` — מרכיב את קובץ ההתקנה העצמאי (`achoti-kalah.html`) ל-`/mnt/documents/`, להעלאה ידנית ל-Drive.
4. `scripts/verify-offline-publish.mjs` — מועבר: מאמת שכל חלק במניפסט קיים, באורך ובחתימה הנכונים, ושהקובץ המורכב תקין.
5. `offline-cdn/updates/manifest.js|json` + `offline-cdn/updates/parts/**` — התוכן שנדחף ל-GitHub ומוגש ע"י jsDelivr.
6. `offline-cdn/parts-registry.json` — מצב אינקרמנטלי.
7. `docs/OFFLINE-ARCHITECTURE.md` + `docs/OFFLINE-PUBLISH.md` — מועברים ומעודכנים לכתובת החדשה; `OFFLINE.md` הקיים יעודכן (הוא כרגע אומר שאין מערכת אופליין כאן).

`ORIGIN` חדש: `https://cdn.jsdelivr.net/gh/<user>/<repo>@main/offline-cdn`
(כך ש-`ORIGIN + "/updates/manifest.js"` ו-`ORIGIN + meta.u` עובדים ללא שינוי בפורמט).
`?origin=` לבדיקות נשמר.

### זרימת פרסום עדכון (מקצה לקצה)
```text
build אופליין  ->  node scripts/pack-offline.mjs --version N
               ->  node scripts/verify-offline-publish.mjs
               ->  push ל-GitHub (סנכרון Lovable עושה זאת אוטומטית)
               ->  purge ל-jsDelivr (purge.jsdelivr.net/gh/...)  ->  התקנות קיימות מתעדכנות בפתיחה הבאה
```
להתקנה ראשונה חדשה: `node scripts/build-offline-package.mjs` ואז העלאה ידנית ל-Drive.

### מה נדרש ממך ידנית
1. לחבר את הפרויקט ל-GitHub (תפריט + בצ'אט → GitHub → Connect) **ולהפוך את הריפו לציבורי** — jsDelivr מגיש רק ריפו ציבורי. לשלוח לי את `user/repo`.
2. אחרי כל פרסום שבו רוצים התקנה ראשונה מעודכנת: להעלות את קובץ ה-HTML שאייצר ל-Google Drive ולהחליף את הקובץ בקישור הקיים.

## סיכונים לדגל
- **jsDelivr + branch**: כתובות `@main` נשמרות ב-cache עד 12 שעות ו-query string לא בהכרח מבטל cache. מיתיגציה: קריאת purge אחרי כל פרסום, ובנוסף אפשרות ל-`@v<N>`-tag אם יידרש. עדכון שמתעכב עד 12 שעות אינו שובר כלום (ההתקנה המקומית ממשיכה לעבוד).
- **מגבלות jsDelivr**: קובץ בודד עד ~20MB (אנחנו ב-44KB לחלק — בטוח), ואין עדיין מדידה של NetFree על *מאות* חלקים עוקבים מ-jsDelivr; הבדיקה שעברה הייתה 32 חלקים. בדיוק בגלל זה ההתקנה הראשונה עוברת ל-Drive, והעדכונים השוטפים הם דלתא קטנה.
- **גודל קובץ ההתקנה**: החבילה המלאה (72 קבצים) ב-base64 תייצר HTML של ~8-9MB. זה בסדר מ-Drive, אבל אם נראה בעיה — אפשר seed של ליבה+תמונות מוקטנות בלבד והשאר בעדכון הראשון.
- **תאימות לאחור נשמרת**: `masked=0`, חלקי 32KB, ערבול חתימת JPEG, חתימת `AK.part`, DJB2 ושדות `u`/`l`/`c` — כולם ללא שינוי, כך שהתקנות קיימות שיקבלו את ה-launcher החדש ימשיכו לפענח חלקים ותיקים.
- **משמעת גודל תמונות** (Project Knowledge): ממשיכה לחול — האורז יתריע על כל קובץ מעל 500KB לפני אריזה.
- **מה שלא נוגעים בו**: auth bridge ב-`achotikala.com/auth-bridge`, `window.ACHOTIKALA_OFFLINE_HOST` + HashRouter, ו-`sync-offline-content` הקיים לתוכן דינמי.
